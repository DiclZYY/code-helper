# 后端规范（Laravel 8 / api）

本规则约束 `api/` 内 Laravel 工程的组织方式、接口风格与工程实践。

## 分层建议（以现状为准，逐步收敛）

- 路由：`routes/`（按业务域拆分）
- 控制器：只做参数接收 / 校验 / 鉴权 / 调用服务层，避免堆业务逻辑
- 服务层（建议）：承载业务编排、事务边界、领域规则
- 模型：表达数据结构与关系，避免把复杂业务塞进 Model

## 参数校验与错误码

- 入参必须校验；校验失败返回统一结构（项目既有格式优先）。
- 错误码（或错误类型）要可追踪与可定位：能找到触发位置与修复负责人。

## 数据库与事务

- 明确事务边界：涉及多表一致性时必须使用事务，并在服务层集中处理。
- 迁移与数据修复：涉及结构变更要有迁移脚本；数据修复需可审计与可回滚（如可行）。

## 日志与审计

- 关键业务操作（登录、权限变更、关键资源修改）需要日志 / 审计记录（以现网要求为准）。
- 日志内容避免包含敏感信息（密码、token、完整身份证 / 手机号等）。

## 全局函数（helpers）

`api/functions/helpers.php` 被 Composer autoload。约束：

- 只允许放「稳定工具函数」，禁止放业务逻辑与带副作用的操作。
- 新增 helper 前优先考虑类方法 / 服务注入，避免全局污染。
