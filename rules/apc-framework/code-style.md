# 编码规范（通用）

跨前后端通用的开发规范。前后端的具体实现细节分别见 `frontend-vue2.md` 与 `backend-laravel.md`。

## Git 分支与提交

- 分支命名建议：`feature/<简述>`、`fix/<简述>`、`chore/<简述>`
- 提交信息建议包含：范围 + 意图（为什么改），避免只写「update / 修改」。
- 重要变更（接口、发布、环境变量、目录结构）必须同步更新 `rules/apc-framework/` 中对应文档。

## 代码变更边界

- 单次改动尽量聚焦一个主题；不要把格式化 / 重排与业务改动混在一起。
- 涉及「跨层调用 / 共享逻辑」的需求，优先通过明确的接口 / 服务层抽象，而不是复制粘贴。

## 接口约定（最低要求）

- API 返回结构、错误码、分页 / 排序参数等要有一致性（若项目已有既定格式，以现有为准；新增模块不得另起炉灶）。
- 前端对后端异常要做到可追踪：至少能定位到接口、参数、错误码 / 错误信息与请求 id（如有）。

## 命名与结构（原则）

- **可读性优先**：命名表达业务含义，避免无意义缩写。
- **同类聚合**：同一业务域的页面 / 接口 / 服务尽量聚合在一起，减少「散落式」代码。
